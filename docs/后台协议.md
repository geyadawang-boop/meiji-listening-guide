# 后台协议 v1

## 传输

Electron 主进程与 TypeScript utilityProcess 使用结构化消息协议。请求经 postMessage / parentPort 传输；stdout/stderr 不作为协议。后台进程隐藏运行，模型凭据由主进程持有，不写入工作进程参数或界面。

请求：`{"protocol":1,"id":1,"action":"list","args":{}}`。

成功响应：`{"protocol":1,"kind":"result","id":1,"ok":true,"result":{}}`。

失败响应：`{"protocol":1,"kind":"result","id":1,"ok":false,"error":"可供用户理解的错误"}`。

id 在各进程连接内递增，用于配对响应。动作来自主进程原生接口允许列表，worker 再校验具体参数及源版本。旧测试适配器允许省略 protocol，视为 v1；显式其他版本拒绝。打包的 worker 响应声明版本。进度/模型控制通知不是最终结果，不应被当成任务完成。

## 模型桥接

research-worker 发出 `kind:model`（key、connection、system、user），主进程验证 connection 后调用当前模型，回传 kind:model-result。取消采用 kind:model-cancel；模型调用中断不自动重试未知结果。桥接中的临时请求带材料，不能把它记录到诊断日志。

## 取消、超时和恢复

知识库串行处理请求；媒体与研究后台可并发响应，以 id 配对。主进程请求超时只说明本次等待停止，不证明持久任务已经取消，应读取任务状态。视觉任务明确取消其本地事件；前台 job 通过 AbortSignal 传播取消。长期下载/研究任务依照持久检查点恢复，完整成果回读校验前不清理证据。

关闭进程、协议损坏或通信断开拒绝当前等待；后台进程的数据库/任务记录保留。源版本、模型变化或用户修改成果时拒绝旧发布；恢复不能覆盖新记录。结果未知的工作流需明确选择重试。

## 诊断

诊断日志只记录组件、事件、操作名、请求编号、预定义错误类别和进程编号，不记录材料正文、联系人消息、cookie、密钥或原始服务 stderr。文件达到约 2 MB 后轮转一份旧日志。日志写入失败不替代原业务错误。

REQUEST_FAILED 表示业务请求失败；INPUT_INVALID 表示主进程输入验证失败；START_FAILED 表示进程不能启动。具体任务错误仍以界面和持久任务记录为准，错误类别不能代替实际失败原因。
