# 验收、数据保护与故障排查

## 发布验收

1. pnpm typecheck 通过；按用户要求，本版本已移除测试脚本，后续用实际构建和启动检查。
2. 完整重建 EXE/安装包，确认 package、ASAR、EXE 文件/产品版本、原生运行环境页面和发布记录一致；Electron 版本单列。
3. 启动最终副本，检查课程/会话、字幕、知识库、研究、通讯以及浅/深/樱花主题；确认自绘标题栏可拖动/最小化/最大化/关闭、按钮层级（每屏一个主按钮、危险操作有二次确认）；使用隔离示例资料，不迁移真实账号进行模拟。
4. 轻量包能启动，在组件缺失时给出安装入口；错版本、篡改文件、越界路径、链接和安装中断不应发布组件。完整包功能不得因减重退化。
5. 校验用户资料和原版未被改变后清理构建/测试暂存，保留最终发行包和真实失败恢复资料。

## 验证矩阵

| 层次 | 可证明的范围 | 不能替代 |
| --- | --- | --- |
| 单元 | 类型规则、状态和输入处理 | 真实服务可用性 |
| 本地集成 | SQLite、文档、真实原生进程和离线向量 | 个人账号及云端模型能力 |
| 副本受控 UI | 实际窗口/按钮、选择、失败恢复及最终导出 | 模型回答语义正确性 |
| 公开接口/媒体 | 当时网址的实际检索/下载 | 所有平台及所有长视频 |
| 用户账号/模型 | 需单独真实验收并记录 | 上述模拟测试不能冒充 |

当前历史验收证据见融合开发进度.md；本次整改结果以整改开发进度.md 的最终记录为准，不能沿用旧版本测试假装验证新构建。

## 常见故障

- 轻量包提示组件缺失：打开「设置 → 运行组件」，选择同版本组件文件夹。不会自动下载安装。组件已存在但损坏时使用完整更新包修复，不覆盖活动后台文件。
- EXE 与页面版本不一致：曾仅替换过 ASAR；使用完整发布重新安装，不能修改显示文字掩盖问题。
- 原生后台/模型不能启动：先检查组件，再查看 userData 或相应资料任务根目录下「诊断日志」以及任务自身记录。不要复制原始账号日志到公开报告。
- 下载/转写超时：读任务记录确认真实状态，不连续重复发起；失败视频和检查点保留。公开接口限流或登录失效应显示实际原因。
- 用户数据看起来为空：检查当前 portable「课程数据」「资料」与 LISTENING_ASSISTANT_DATA；测试目录不能作为生产目录。不要删除原数据库或拿其他学年代替。
- 原生模块 ABI 错误：按 pnpm-lock.yaml 重新安装依赖并重建 Electron 依赖；Node 用的二进制不能直接代替 Electron 版本。
- 媒体下载工作进程启动失败（存量缺陷，待修复）：`out/main/media-download-worker.js` 依赖的共享分块顶层引入 electron `app`，utilityProcess 下抛 `SyntaxError`；`pnpm runtime:smoke` 的 seed 阶段会暴露该问题。

## 备份与迁移

关闭软件后备份整个「课程数据」及「资料」目录，保持文件位置关系。机器账号和设置在 userData，需要另行保护，不随程序分发。portable 初始化有旧课程迁入逻辑；无意迁入时先停下确认根目录，不自动删除资料。

升级只替换发布清单内的程序/运行资源，保留其他目录。更新失败必须可恢复旧程序；不要强制结束用户任务或用递归清理删数据库。教材批注、独立下载视频和已核验 PDF 属于用户最终成果。
