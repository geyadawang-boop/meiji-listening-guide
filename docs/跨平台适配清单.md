# 跨平台适配清单（macOS / Linux）

本分支已完成三平台 lite 安装包构建与 macOS 开发运行。要真正在 macOS/Linux 上提供完整功能，需要后端按本清单逐项适配。条目按阻塞程度排序，均已标注当前代码位置。

## 一、运行时阻塞项

### 1. 系统加密与进程管理（影响面最大）

- `src/main/windows-native.ts`：koffi 加载 `kernel32.dll`/`crypt32.dll`，使用 DPAPI（`CryptProtectData`）与 Windows Job Object；非 Windows 平台在被调用时抛「此系统组件需要 Windows x64」（windows-native.ts:5）。
- 消费方：
  - `src/main/media-auth.ts`：登录档案 `profiles.dpapi`
  - `src/main/media-jobs.ts`：加密任务记录 `job.dpapi`
  - `src/main/im-store.ts`：`im-connections.sqlite3` 的 `connections.sealed/session`
  - `src/main/im-napcat-runtime.ts`：`native-owner.dpapi`
  - `src/main/im-weixin-local.ts`：`NativeWindowsJob` 托管子进程

媒体加密已通过受限字节消息接入主进程 `safeStorage`：`media-auth.ts`/`media-jobs.ts` 在 utilityProcess 中异步等待结果后再写入。Windows 保留原 DPAPI 字节和文件名；macOS/Linux 使用带媒体域、版本与平台标记的密文，拒绝不可用密钥库及 Linux 不安全/未知后端。密文不支持跨系统迁移，原文件不自动覆盖。实际 macOS/Linux 密钥库仍待实机验收。

通讯凭据位于 research utilityProcess，现通过独立字节通道使用主进程系统密钥库；凭据、会话与 QQ owner 文件保持原位置，Windows 旧密文兼容。新平台密文使用独立通讯域标记，不能与媒体密文混用。等待加密期间连接、账号或登录状态改变时拒绝过期写入并保留原记录。实际 macOS/Linux 密钥库仍待验收。Windows Job Object 仍待独立 POSIX 生命周期方案，不能直接收养任意 PID 或杀不明进程组。

### 2. FFmpeg / FFprobe

- 媒体、课件画面与本地字幕入口统一通过 `media-executable.ts` 解析工具：Windows 使用 `ffmpeg.exe`/`ffprobe.exe`，macOS/Linux 使用无扩展名版本；只接受这两个固定工具，不搜索系统 PATH。
- 执行前检查普通文件、资源目录内路径、父目录链接及 POSIX 执行权限；媒体守护进程使用相同检查。
- 尚未引入或验证 macOS/Linux 二进制、许可包和签名。当前 `extraResources`、运行清单及组件发布仍按 Windows 资源处理；非 Windows portable/lite 不夹带这些组件。路径适配不等于组件已安装或可运行。

### 3. 千问 API 连接（已替换旧账号组件）

- `src/main/api.ts`、`src/main/settings.ts` 和 `src/renderer/src/QwenSettings.tsx` 使用用户配置的千问兼容 API，分别选择文本与视觉模型。
- ChatGPT/Codex 账号入口、DeepSeek 专用连接及 Codex CLI 组件已移除；无需为 macOS/Linux 移植 Codex 二进制。旧凭据保留在原存储字段，千问不会继承它们。

待验收：各平台的 API 连通性、系统密钥存储、实际可用模型和视觉输入；此迁移不代表媒体及其他 Windows 专属功能已适配。

### 4. 本机微信只读（Windows 专属）

- `src/main/im-weixin-process.ts:6`（kernel32/ntdll 内存扫描）、`src/main/im-weixin-local.ts`、`src/main/im-weixin-local-worker.ts`。

已在后台及界面按实际平台能力限制：本机微信仅 Windows x64 可启动读取；其他平台保留已保存会话与消息查看，不解密会话、不启动读取进程。暂不移植内存扫描。

### 5. QQ / 通讯后台（NapCat）

- `src/main/im-napcat-runtime.ts:37,54`：依赖 `resources/knowledge/vendor/NapCat.Shell.Windows.Node.zip` 内的 `node.exe`，并用 `NativeWindowsJob` 托管。

当前内置 NapCat 仅 Windows x64，后台在解包和启动前拒绝其他平台，界面禁用并说明；手工连接已有 QQ 服务仍保留。Linux 组件与进程托管尚待独立适配及实机验收。

### 6. 旧模型账号登录浏览器（已移除）

- 旧 Codex 账号登录浏览器随账号入口移除，千问使用 API Key 配置，不再需要探测 Chrome 路径。
- 智云、媒体等其他登录流程仍需各平台独立验收，不因模型连接替换而视为已支持。

### 7. 平台守卫与提示

- 运行组件安装已有双层守卫：`src/main/ipc/desktop.ts` 拒绝非 Windows 安装，`src/renderer/src/RuntimePanel.tsx` 禁用入口并说明限制；尚不代表组件本身完成跨平台适配。

- `src/main/windows-native.ts:5`、`src/main/im-weixin-process.ts:6`、`src/main/im-weixin-process.ts:20` 等仅在调用时抛错。建议渲染层按 `app:info` 返回的 `platform` 提前禁用入口，并给出「该功能暂仅支持 Windows」提示（`src/main/ipc/desktop.ts:25` 已返回平台字段）。

## 二、打包与资源侧

- `resources/runtime-manifest.json`：保留 knowledge/asr/video 三个组件，Codex 组件已移除；现有包仍包含 Windows 专属资源（`ffmpeg.exe`、NapCat Windows zip）。需要「每平台一套组件包」或按平台字段拆分。
- `package.json` 的 `extraResources` 过滤（ffmpeg.exe 白名单）、`scripts/runtime-manifest.mts` 的 `included()` 需平台化；本分支已放宽 `asarUnpack`（`@koromix/**`、`better-sqlite3-multiple-ciphers/**`、`onnxruntime-node/**`）。
- 安装/校验逻辑 `src/main/runtime-components.ts` 本身平台无关，可直接复用，前提是每平台有对应 manifest 与组件包。
- 签名：macOS 发行需要 Developer ID 签名 + 公证，Windows 需要代码签名证书；当前 CI 产物未签名（mac 首次打开需右键「打开」，Windows 会触发 SmartScreen）。

## 三、构建与 CI 现状

- 三平台 lite 安装包（无组件）由 `.github/workflows/release.yml` 构建；Windows 完整包仍需在有组件的机器上本地执行 `pnpm build && pnpm release full`。
- 依赖锁文件为 `pnpm-lock.yaml`（平台无关，含各平台可选依赖）；迁移前的 `package-lock.json` 曾在 Windows 上生成、缺少 darwin/linux 可选二进制（`@esbuild/*`、`@koromix/koffi-*`、`@napi-rs/canvas-*` 等），已在切换前补齐。后续请勿用 `--omit=optional` 或平台参数重新生成锁文件。
- `scripts/release.mts`：`full` 仅允许 Windows；`lite`/`portable` 支持三平台；`--prepared` 使用仓库内 `runtime-manifest.json`（升级版本号时需同步该文件的 `productVersion`）。
- `scripts/audit-typescript.mts` 依赖本机安装副本 `../梅酱的听课指南-副本` 和未声明的 `@electron/asar`，无法在干净 CI 中运行，已不纳入流水线。
- CI 使用 Node 24、`pnpm install --frozen-lockfile`（postinstall 会重建 Electron ABI 原生模块）和 `pnpm verify`（全量 typecheck + Biome format/lint，不过不给过），macOS 使用 `macos-14`（arm64）runner。注意 `pnpm ci` 是 pnpm 内置的冻结安装命令，不能用作校验入口。

## 四、验收建议

1. 每平台：安装 → 启动 → 课程库、知识库、教材批注、导出全流程。
2. 逐项打卡：媒体下载/合并（ffmpeg）、本地 ASR、千问 API 配置、文本对话与视觉模型输入、登录档案加密、QQ/微信（可暂标不支持）。
3. 回归：Windows full 包功能与现有 0.1.85 验收一致，不得因跨平台改动退化。
4. 安全：改用 `safeStorage` 后需复测登录档案与加密任务记录的密文读写、越界路径与符号链接校验（沿用 `runtime-components.ts` 的校验思路）。
